# Архитектура. Система учёта рабочего времени и задач сотрудников проектной организации

## Три узла системы

```
┌──────────────────────┐       HTTP         ┌──────────────────────┐    SQL-запросы   ┌──────────────────────┐
│                      │  ──────────────►   │                      │  ─────────────►  │                      │
│   Vue 3 + Vite       │                    │   ASP.NET Core       │                  │   PostgreSQL         │
│   localhost:5173     │  ◄──────────────   │   localhost:5000     │  ◄─────────────  │   localhost:5432     │
│                      │       JSON         │                      │      данные      │                      │
└──────────────────────┘                    └──────────────────────┘                  └──────────────────────┘
   что видит человек                          правила системы                          где лежат данные
   в браузере                                 (проверка, валидация)                    (таблицы Task, Project, User)
```

**Пример запроса между узлами:**

```
Vue  ──[ POST /api/tasks ]──►  ASP.NET Core  ──[ INSERT INTO task ... ]──►  PostgreSQL
Vue  ◄──[ 201 Created, JSON ]──  ASP.NET Core  ◄──[ подтверждение ]──────  PostgreSQL
```

---

## Роли узлов

### Vue 3 + Vite (порт `5173`)

**Что делает:** рисует экраны в браузере (список задач, форма создания, вход). Отправляет HTTP-запросы к серверу. **Не хранит данные** — только показывает то, что пришло с сервера.

**Ключевое правило:** Vue **не общается с PostgreSQL напрямую**. Иначе браузер получил бы доступ к базе, а это значит — любой пользователь мог бы обойти правила сервера (например, закрыть чужую задачу или удалить запись).

### ASP.NET Core (порт `5000`)

**Что делает:** принимает HTTP-запросы от Vue. Проверяет правила: валидация полей, кто имеет право менять задачу, допустимы ли переходы статусов. Делает запросы к базе. Возвращает JSON обратно в браузер.

**Ключевое правило:** все решения «можно / нельзя» — только здесь. Сервер доверяет только себе, а не тому, что прислал клиент.

### PostgreSQL (порт `5432`)

**Что делает:** хранит таблицы `Task`, `Project`, `User`. Данные не теряются при перезапуске сервера.

**Ключевое правило:** база не знает про HTTP. Она принимает SQL-запросы только от ASP.NET Core. К ней не подключиться из браузера.

---

## Почему браузер не пишет в базу напрямую

Если бы Vue мог обращаться к PostgreSQL напрямую:

1. **Правила сервера обходились бы.** Сотрудник мог бы закрыть чужую задачу или назначить себя без разрешения — просто отправив SQL-запрос.
2. **Данные были бы открыты.** Любой пользователь с инструментами разработчика увидел бы структуру базы и все записи.
3. **Пароль к базе пришлось бы отдать в браузер.** А значит — любому, кто откроет исходный код страницы.

Поэтому цепочка всегда такая:

```
Vue  →  ASP.NET Core  →  PostgreSQL
```

А не так:

```
Vue  →  PostgreSQL   ← ТАК НЕЛЬЗЯ
```

## Текстовая версия схемы

Если диаграмма не отображается, вот та же схема словами:

1. **Vue 3 + Vite**, порт `5173` — клиент, который работает в браузере пользователя.
2. **ASP.NET Core**, порт `5000` — сервер, который принимает HTTP-запросы и проверяет правила.
3. **PostgreSQL**, порт `5432` — база данных, где хранятся таблицы.

Стрелки:
- Vue → ASP.NET Core: HTTP-запросы (например, `POST /api/tasks`)
- ASP.NET Core → Vue: JSON-ответы (`201 Created`, `200 OK`)
- ASP.NET Core → PostgreSQL: SQL-запросы (чтение и запись)
- PostgreSQL → ASP.NET Core: результаты запросов (строки таблиц)
