Связь трёх обязательных критериев приёмки из `lab-01-requirements.md` с моделью данных (`data-model.md`) и API (`api-contract.md`).

## Разбор по критериям

### Критерий 1. Создать задачу

**Дано:** руководитель проекта вошёл в систему.

**Когда:** он заполняет три поля:
- `title` (5–80 символов)
- `projectId` (число, ссылка на `Project.id`)
- `description` (10–500 символов)

**Что происходит на сервере:**
1. Проверяет валидацию полей → при ошибке `400`
2. Проверяет, что `projectId` существует → при отсутствии `400`
3. Генерирует `number` в формате `TASK-2026-XXXX`
4. Устанавливает `status = "New"`
5. Записывает `createdByUserId` из сессии пользователя
6. `assigneeUserId` пока пустой

**Результат:** `201 Created` с полным объектом задачи.

**Запрос:** `POST /api/tasks`

---

### Критерий 2. Назначить исполнителя

**Дано:** руководитель проекта и задача в статусе `New`.

**Когда:** он отдельным действием назначает сотрудника-исполнителя.

**Что происходит на сервере:**
1. Проверяет, что задача существует → иначе `404`
2. Проверяет, что `assigneeUserId` — существующий пользователь → иначе `404`
3. Записывает `assigneeUserId` в задачу
4. **Статус не меняет** — остаётся `New`

**Результат:** `200 OK` с обновлённой задачей.

**Запрос:** `PATCH /api/tasks/{id}/assignee`

**Отличие от критерия 3:** это отдельный запрос. Один `PATCH` не делает и назначение, и смену статуса сразу.

---

### Критерий 3. Исполнитель перевёл в работу

**Дано:** назначенный сотрудник вошёл в систему.

**Когда:** он переводит **свою** задачу из `New` в `InProgress`.

**Что происходит на сервере:**
1. Проверяет, что задача существует → иначе `404`
2. Проверяет, что текущий пользователь — это `assigneeUserId` этой задачи → иначе `403` (отказ в доступе)
3. Проверяет, что переход `New → InProgress` допустим → иначе `409`
4. Меняет `status` на `InProgress`

**Результат:** `200 OK` с обновлённой задачей.

**Запрос:** `PATCH /api/tasks/{id}/status`

**Ключевое правило:** чужой сотрудник ту же задачу не двигает — сервер проверяет `assigneeUserId`.

## Проверка полноты

| Что должно быть | Где это в матрице |
|-----------------|-------------------|
| Создание задачи | Критерий 1 — `POST /api/tasks` |
| Назначение исполнителя | Критерий 2 — `PATCH .../assignee` |
| Смена статуса | Критерий 3 — `PATCH .../status` |
| Роли с разным правом | Критерий 3 — проверка `assigneeUserId` |
| Запрет на чужую задачу | Критерий 3 — ответ `403` |
| Отмена как `Cancelled`, а не удаление | Раздел «Допустимые переходы статусов» в `api-contract.md` |

Все три критерия из ЛР1 связаны с моделью и API. Матрица полная.
